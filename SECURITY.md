# Privacy and security

Use this tool only for a device you own or are explicitly authorized to administer.

## What stays private

Do not submit a NAS address/hostname, account UID, account name/password, certificate, private key, original NAS configuration, recovery journal, real host-key fingerprint, personal file path, photo, backup receipt or raw runtime log to an issue, pull request or release. Recovery journals can contain a temporary administrative password until cleanup is verified. Keep them outside the checkout and owner-readable only.

Public diagnostics deliberately return a small allowlist of booleans/version information. Unexpected exceptions suppress their raw text. The code has no telemetry, credential upload or remote callback. The operator's NAS management connection uses the provided CA and hostname validation; SSH uses strict host-key checking. Bootstrap temporary SMB sessions require encryption.

## Boundaries

- One LAN address at a time; no network scanning or remote mass execution.
- Existing SSH listener or loader configuration causes refusal.
- Device keys are supplied/generated by the operator, never bundled.
- No unauthenticated root listener, password guessing, public port mapping, formatting, downgrade or user-file cleanup.
- The generated SSH service includes `-s` (password authentication disabled). `-B` permits the firmware's blank-password **account** to use key authentication; it does not enable password or `none` authentication when combined with `-s`. Verification checks rejection without a key.
- Bootstrap briefly changes Samba account/share configuration and may reconnect active shares. The service/account changes require explicit experimental apply flags and a maintenance window.
- The delayed cleanup is best-effort. It can be interrupted by reboot, power loss, process termination or connectivity failures. Preserve local recovery state and independently verify the temporary account is gone; do not infer success from a queued request or open SSH port.
- Never overwrite an unfamiliar loader file or a pre-existing installation. Rollback restores the recorded root entry only and preserves unrelated accounts; created setup files are retained for review.

For a security report, use GitHub's private vulnerability reporting if available on the repository. Otherwise do not post exploit credentials or personal logs publicly; first open a content-free issue asking for a private reporting channel. There is no personal contact address embedded in this repository.
